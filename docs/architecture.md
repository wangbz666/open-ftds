# 架构与并发模型

## 数据路径

```text
业务线程 START/END 或 record
          │
          ▼
按 event_id 查找固定槽位（最多 4096 个）
          │
          ▼
事件级短自旋锁更新 count/errors/total/min/max/histogram
          │
          ▼
后台线程按周期交换并清零区间统计
          │
          ▼
data/stat/*.ios（JSON Lines，按大小轮转）
          │
          ▼
openftds-report 离线合并与排序
```

注册新事件时才使用全局 registry mutex；稳定运行后，已有事件只竞争自己的短自旋锁。
flush 使用独立 mutex，保证手动 flush 与后台 flush 不会并发写同一文件。

## 生命周期

`openftds_init()` 初始化进程级单例、目录、输出文件和后台线程。重复调用返回成功但不修改
现有配置。首次埋点可以自动初始化。`openftds_shutdown()` 唤醒并回收后台线程、执行最后
一次 flush、关闭文件；重复调用安全。

## 聚合语义

每个 flush 区间输出有调用的事件。输出后该区间的计数清零，因此 `.ios` 中的行是增量而
非进程启动以来的累计值。报告工具可跨文件、进程和区间合并同一
`event_id/module/name/level`。

直方图是 32 个以微秒为单位的 log2 桶。平均值使用纳秒总和精确计算；P50/P95/P99 是桶
上界近似值。这一设计使每个事件的内存和每次记录的工作量固定。

## 失败模型

- 创建目录或输出文件失败时，初始化返回 errno 风格的非零值。
- 后台线程创建失败会记录日志；调用方仍可手动 `openftds_flush()`。
- `SIGKILL`、主机断电或文件系统故障可能丢失当前未 flush 区间。
- 超过 4096 个不同事件 ID 后，新事件被丢弃并写客户端日志。
- 名称最长 95 字节、模块最长 47 字节，超过部分被截断。

## fork 与信号

每个 API 入口在获取任何锁前检查 PID。fork 子进程第一次调用时会关闭继承的输出描述符、
丢弃父进程聚合副本、重建同步对象和事件表，并沿用配置懒启动自己的后台线程。这样不会
继承父进程中可能由其他线程持有的锁，也不会重复输出父进程尚未 flush 的数据。

推荐在 worker fork 后、创建新的业务线程前主动调用一次 `openftds_init(NULL)`，让恢复时点
可预测。库函数不是 async-signal-safe，不应从信号处理函数直接调用。
